# TT Ambassador Portal

Вътрешна платформа на **Todorov Tees** за управление на амбасадори, проследяване на комисиони и заявки за изплащане. Интерфейсът е изцяло на български език.

> Това **не** е система за автоматично проследяване на партньорски връзки. Продажбите се въвеждат ръчно от администратор. Изплащанията се извършват ръчно през Revolut.

## Функционалности

**За амбасадори:** табло с наличен баланс, история на продажбите (само за четене), заявки за теглене на комисиона през Revolut с 60-минутен прозорец за редакция, известия, брандирани ресурси, редактируем профил.

**За администратори:** пълно управление на амбасадори (покана със сигурна настройка на парола — админът никога не вижда паролата), ръчно въвеждане на продажби с автоматично изчисление на комисиона, одобрение/отказ/маркиране на изплащания, преглед на кандидатури от лендинг страницата, качване на ресурси, одит лог на всички критични действия, конфигурируеми настройки.

**Сигурност:** хеширани пароли (Supabase Auth, bcrypt), Row Level Security на ниво база данни (не само frontend проверки), сървърна проверка на всяко действие, одит лог, защита срещу достъп до чужди данни чрез промяна на ID в URL.

## Технологичен стек

| Слой | Технология |
|---|---|
| Frontend | Vanilla HTML5 / CSS3 / JavaScript (ES modules), без framework |
| Backend / Auth / DB | [Supabase](https://supabase.com) (PostgreSQL + Auth + Storage + Edge Functions) |
| Хостинг на frontend | GitHub Pages (или всеки статичен хостинг) |
| Имейли | [Resend](https://resend.com) (през Edge Function) |
| Плащания | Ръчни, през Revolut |

Защо Supabase: осигурява истинска релационна база данни, хеширане на пароли по подразбиране (не се пази никъде в plaintext), и Row Level Security — правилата за достъп се прилагат в самата база данни, така че дори при пропуск във frontend кода, амбасадор физически не може да прочете чужди данни или да пише в защитени таблици.

## Инсталация

### 1. Създайте Supabase проект
1. [supabase.com](https://supabase.com) → New Project
2. Запишете си **Project URL** и **anon public key** (Project Settings → API)

### 2. Приложете схемата на базата данни
```bash
npm install -g supabase
supabase login
supabase link --project-ref YOUR-PROJECT-REF
supabase db push
```
Това изпълнява `supabase/migrations/0001_init.sql`, който създава всички таблици, тригери и Row Level Security политики.

### 3. Създайте Storage bucket за ресурси
В Supabase Dashboard → Storage → New bucket → `resources` (public).

### 4. Деплойнете Edge Functions
```bash
supabase functions deploy admin-create-ambassador
supabase functions deploy notify-payout-event

supabase secrets set SUPABASE_SERVICE_ROLE_KEY=xxx
supabase secrets set SITE_URL=https://your-username.github.io/tt-ambassador-portal
supabase secrets set RESEND_API_KEY=xxx
supabase secrets set NOTIFY_FROM_EMAIL=portal@todorovtees.com
```

### 5. Конфигурирайте имейл шаблоните на Supabase Auth
Authentication → Email Templates → персонализирайте поканата ("Invite user") и възстановяването на парола на български, ако желаете.

### 6. Настройте frontend конфигурацията
```bash
cp js/config.example.js js/config.js
```
Отворете `js/config.js` и попълнете `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Този файл е в `.gitignore` — никога не се качва в GitHub.

> `SUPABASE_ANON_KEY` е публичен по дизайн и е безопасен за frontend — реалната защита идва от Row Level Security политиките в базата данни, не от тайната на този ключ.

## Настройка на базата данни

Основни таблици (виж пълната схема в `supabase/migrations/0001_init.sql`):

| Таблица | Описание |
|---|---|
| `profiles` | Разширява `auth.users` с роля, комисиона, статус |
| `sales` | Продажби, въведени от админ; комисионата се "снимка" при създаване |
| `payout_requests` | Заявки за теглене с автоматично номериране и 60-мин. прозорец за редакция |
| `notifications` | Известия по потребител |
| `resources` | Брандирани материали |
| `applications` | Кандидатури от публичната страница |
| `settings` | Глобални настройки (един ред) |
| `audit_logs` | Автоматичен одит лог |

Ключова бизнес логика, реализирана директно в базата данни (тригери), а не само във frontend:
- Комисионата се изчислява и "замразява" при създаване на продажба — последващи промени на процента на амбасадора не променят стари продажби.
- Наличният баланс се изчислява от одобрени продажби минус вече заявени/изплатени суми — невъзможно е да се създаде заявка над наличния баланс, дори при паралелни заявки.
- Заявка за изплащане може да се редактира само от собственика ѝ, само в статус "Подадена", само до 60 минути след създаване.

## Локална разработка

Тъй като сайтът е статичен, всеки локален сървър работи:
```bash
npx serve .
# или
python3 -m http.server 5173
```
Отворете `http://localhost:5173`.

За тест на Edge Functions локално:
```bash
supabase functions serve
```

## Деплойване

**Frontend → GitHub Pages:**
```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/YOUR-USERNAME/tt-ambassador-portal.git
git push -u origin main
```
После: Settings → Pages → Deploy from branch → `main` / root.

**Backend → вече е на Supabase** (managed PostgreSQL + Auth + Storage + Edge Functions), не изисква отделен сървър.

Не забравяйте да обновите `SITE_URL` secret-а на Edge Functions с реалния GitHub Pages адрес, за да работят коректно линковете за покана/възстановяване на парола.

## Бележки по сигурността

- Паролите никога не се пазят в код, база данни в plaintext, localStorage или логове — Supabase Auth ги хешира автоматично.
- Администраторът никога не вижда пароли — създава амбасадор чрез сигурна имейл покана (`admin-create-ambassador` Edge Function), амбасадорът сам задава паролата си.
- `SUPABASE_SERVICE_ROLE_KEY` съществува само като Supabase secret, използван вътре в Edge Functions — никога не достига до браузъра.
- Всяка таблица има Row Level Security политики — дори директна манипулация на заявки от браузъра не може да заобиколи проверките за роля/собственост.
- Одит логът записва вход/изход, промени по амбасадори, продажби и заявки за изплащане автоматично чрез database triggers.

## Настройка на администратор

Първият администраторски профил трябва да се създаде ръчно веднъж:
1. Supabase Dashboard → Authentication → Add user → въведете имейл и парола (или изпратете покана).
2. SQL Editor → изпълнете:
```sql
insert into public.profiles (id, role, first_name, last_name, email, commission_rate, status)
values ('USER-UUID-FROM-AUTH-USERS', 'admin', 'Име', 'Фамилия', 'admin@todorovtees.com', 0, 'active');
```
От тук нататък всички следващи администратори/амбасадори могат да се управляват през интерфейса.

## Настройка на амбасадор

Администраторът добавя амбасадор през **Админ → Амбасадори → + Добави амбасадор**. Системата изпраща имейл покана; амбасадорът кликва линка, задава своя парола и влиза directно в таблото си.
